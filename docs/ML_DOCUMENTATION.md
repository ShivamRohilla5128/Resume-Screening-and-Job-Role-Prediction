# Machine Learning Documentation

## 1. Problem statement
Recruiters receive many unstructured resumes (PDF/DOCX). Reading them manually is slow and inconsistent. The task: (a) classify a resume into a job category from its text, (b) measure its compatibility with a job description, and (c) explain gaps - without making hiring decisions.

## 2. Objectives
Extract text and fields; predict the most suitable role (multi-class text classification); compute a transparent job-match score; identify missing skills and build a personalised roadmap; rank multiple resumes; keep everything explainable and privacy-preserving.

## 3. Existing system
Keyword filters in applicant-tracking tools: brittle exact-match rules, no probabilities, no explanation, and prone to rejecting good candidates who use different wording.

## 4. Proposed system
A supervised TF-IDF text classifier (Logistic Regression / Random Forest / linear SVM compared by cross-validation) for role prediction; TF-IDF cosine similarity combined with explicit skill matching for job fit; rule-based skill-gap and review modules; human-in-the-loop by design.

## 5. Dataset
* Required: a public labelled resume dataset (Kaggle *Resume Dataset* by snehaanbhawal; Kaggle *Updated Resume Dataset* by gauravduttakiit; or Hugging Face). See `ml/datasets/README.md` for links, column handling and the licence/attribution reminder.
* **Bundled demo data:** `resume_dataset_synthetic.csv` - 750 **synthetic** resumes (15 roles x 50), generated by `generate_synthetic_dataset.py` with cross-role skill noise, off-topic bullets and generic titles. Columns: `Resume_ID, Resume_Text, Category, Skills, Education, Experience`. It exists only to test the code path.
* Separate `skills_reference.csv` (15 roles x required/optional skills) is a reference table, not training data.

## 6. Preprocessing (`ml/preprocessing/text.py`)
Drop missing rows -> lowercase -> remove e-mails, URLs, phone numbers -> tokenise (keeps `c++`, `c#`, `node.js`, `ci/cd`) -> stop-word removal -> light rule-based lemmatisation (plural stripping; skill terms protected so "pandas" stays "pandas") -> **duplicate removal on cleaned text** (prevents train/test leakage) -> label encoding -> class-imbalance analysis (counts and max/min ratio saved in `metrics.json`; `class_weight="balanced"` used). Classes with fewer than 10 samples are dropped. NLTK/spaCy are not required; the tokeniser/lemmatiser are self-contained so the project installs offline-friendly.

## 7. Feature extraction
`TfidfVectorizer(ngram_range=(1,2), sublinear_tf=True, min_df=2, max_df=0.9, max_features=20000)`. Feature selection is performed by the document-frequency cut-offs and the vocabulary cap. The vectorizer is part of each sklearn `Pipeline`, so it is re-fitted on training folds only.

## 8. Algorithms
Logistic Regression (C=10, balanced); Random Forest (300 trees, balanced); Linear SVM (`LinearSVC`, balanced) wrapped in `CalibratedClassifierCV` to obtain probabilities.

## 9. Training and selection
80/20 stratified split (seed 42). Each pipeline is scored with 5-fold stratified CV (macro-F1) **on the training split**; the best CV model is selected (the test set is never used for selection), fitted, evaluated once on the test split, and saved with Joblib: `resume_classifier.pkl`, `tfidf_vectorizer.pkl`, `label_encoder.pkl`, `skill_extractor.pkl` (+ `metrics.json`). The API loads them once at startup and never retrains. Note: the saved final model is fitted on the 80% training split (so reported test metrics describe exactly the shipped model).

## 10. Evaluation
Accuracy, weighted/macro precision, recall, F1, per-class classification report and confusion matrix for every model (`metrics.json`; rendered in the app and in `docs/ML_RESULTS.md`, regenerated with `python -m ml.evaluation.make_report`). **The committed results come from the synthetic dataset and must be regenerated after training on real data before they are quoted anywhere.**

## 11. Explainability
For the predicted class the top contributing n-grams are `weight_c[feature] x tfidf[feature]` (linear models, including the calibrated SVM's averaged coefficients) or `feature_importance x tfidf` (Random Forest). The UI also lists detected skills that belong to the role. The displayed probability is the classifier's output only and is never presented as hiring or employability likelihood.

## 12. Matching, gap analysis, review
See README "Matching score". Gap analysis compares detected skills with `skills_reference.csv`, groups missing skills by difficulty, creates phases/week estimates from them, and greedily selects practice projects that cover the most missing skills - so two candidates get different roadmaps.

## 13. Limitations
Synthetic demo data; public datasets are small, noisy and biased and cover few of the 15 roles; text can encode demographic proxies even without names; rule-based parsing misses unusual layouts; no OCR; the vocabulary-based skill detector has limited coverage; the cosine scaling constant (0.35) and the weights are heuristics, not learned.

## 14. Future scope
Real multi-source dataset with licence-checked attribution; transformer embeddings (e.g. sentence-transformers) as an additional model; learned skill extraction (NER); OCR for scans; bias audits across resume sub-groups; calibrated score weights from recruiter feedback; e-mail delivery for password reset; refresh tokens and persistent rate limiting.
